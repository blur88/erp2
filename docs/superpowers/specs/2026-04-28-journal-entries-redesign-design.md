# Journal Entries Redesign — Design Spec

**Issue:** #464  
**Date:** 2026-04-28  
**Status:** Approved

## Overview

Redesign the Journal Entries module to be a read-only list page that follows the UI and architectural standards established by the Chart of Accounts, Sales Orders, and Purchase Orders pages. All manual mutation actions are removed because journal entries are automatically generated by other modules.

## Scope

### Deleted
- `frontend/src/pages/accounting/JournalEntryFormPage.tsx`
- `frontend/src/pages/accounting/__tests__/JournalEntryFormPage.test.tsx`
- Routes `/accounting/journal-entries/new` and `/accounting/journal-entries/:id/edit` from `router.tsx`
- Lazy import of `JournalEntryFormPage` from `router.tsx`

### Modified
- `JournalEntriesTable.tsx` — rewritten to use `EntityTable`
- `JournalEntryContextHeader.tsx` — rewritten as read-only info strip
- `JournalEntryWorkspaceCard.tsx` — layout aligned to `OrderWorkspaceCard`
- `useJournalEntriesWorkspace.ts` — mutation logic stripped, `focusedIndex` added
- `JournalEntriesPage.tsx` — bulk toolbar, dialogs, and all action callbacks removed
- `router.tsx` — form routes removed
- Test files for the above components updated accordingly

## Architecture

The Journal Entries module becomes a **read-only list page**. It follows the same architecture as other list pages in the app:

```
GenericListPage
├── filterBar (search, period, status, entry type)
├── listSlot → JournalEntriesTable (wraps EntityTable)
├── headerSlot → JournalEntryContextHeader (read-only)
└── workspaceSlot → JournalEntryWorkspaceCard (ledger lines)
```

No `primaryAction` button, no `contentSlot` bulk toolbar, no dialogs.

## Components

### JournalEntriesTable

Thin wrapper around `EntityTable`. Columns:

| Key | Content |
|-----|---------|
| reference | `referenceNumber` (primary.main, fontWeight 500) |
| date | `entryDate` formatted |
| description | truncated to 220px |
| type | `Chip` using `ENTRY_TYPE_LABELS` |
| source | `Link` button → navigateToSource (hidden for manual/no sourceId) |
| debits | `totalDebits` right-aligned |
| credits | `totalCredits` right-aligned |
| status | `EntityStatusChip` |

Props: `entries`, `loading`, `total`, `selectedEntryId`, `focusedIndex`, `onSelect`, `listRef`.

No checkboxes, no per-row action buttons.

### JournalEntryContextHeader

Read-only header using `EntityContextHeaderBar` + detail table. Matches `OrderContextHeader` style.

- **Empty state:** "Select a journal entry to view details" centered in a Paper.
- **Header bar:** title = `referenceNumber`, status chips = `EntityStatusChip(status)` + type chip. No actions slot.
- **Detail table:** two-column label/value layout (matching `OrderContextHeader`'s `detailTableSx`):
  - Date, Description, Total Debits, Total Credits
  - Source link row (only shown when `sourceType` and `sourceId` are present)

Props: `selectedEntry: JournalEntry | null`, `onNavigateToSource: (path: string) => void`.

### JournalEntryWorkspaceCard

Minor layout changes to match `OrderWorkspaceCard`:

- Section title ("Ledger Lines") rendered inside a `TableContainer/Table/TableBody/TableRow` pattern matching the "SO Items" heading row in `OrderWorkspaceCard`.
- Unbalanced `Alert` placed inside the scrollable content area (below the heading row).
- Ledger lines table unchanged.

### useJournalEntriesWorkspace

**Kept:**
- `selectedEntry`, `setSelectedEntry`
- `focusedIndex`, `setFocusedIndex` (new — tracks array index of selected row)
- `searchInputRef`, `listRef`
- `handleSelect` (fetches full entry via lazy query)
- `navigateToSource`

**Removed:**
- `selectedIds`, `handleToggleCheck`, `handleSelectAll`
- `postTarget`, `setPostTarget`, `handleConfirmPost`
- `deleteTarget`, `setDeleteTarget`, `handleConfirmDelete`
- `reverseTarget`, `setReverseTarget`, `handleConfirmReverse`
- `bulkPostOpen`, `setBulkPostOpen`, `handleBulkPost`
- `bulkDeleteOpen`, `setBulkDeleteOpen`, `handleBulkDelete`
- `actionLoading`
- `navigateToCreate`
- `navigateToEdit`

`handleSelect` sets both `selectedEntry` and `focusedIndex` (the index is passed in from the page, which gets it from the entries array).

### JournalEntriesPage

**Removed:**
- `primaryAction` prop from `GenericListPage`
- `contentSlot` (bulk Post/Delete toolbar)
- All dialog imports and `JournalEntriesDialogs` usage
- All action callback props passed to `JournalEntryContextHeader`
- `workspace.selectedIds`, `workspace.setBulkPostOpen`, `workspace.setBulkDeleteOpen`

**Kept:**
- Filter bar, sort, pagination
- `listSlot` → `JournalEntriesTable`
- `headerSlot` → `JournalEntryContextHeader` (read-only)
- `workspaceSlot` → `JournalEntryWorkspaceCard`
- `AccountMappingWarning`

### router.tsx

Remove:
```tsx
const JournalEntryFormPage = React.lazy(() => import('./pages/accounting/JournalEntryFormPage'))
{ path: '/accounting/journal-entries/new', element: <JournalEntryFormPage />, ... }
{ path: '/accounting/journal-entries/:id/edit', element: <JournalEntryFormPage />, ... }
```

The existing catch-all `{ path: '/accounting/journal-entries/:id', element: <Navigate to="/accounting/journal-entries" replace /> }` stays, so old deep-links redirect cleanly.

## Data Flow

1. `JournalEntriesPage` fetches entries via `useGetJournalEntriesQuery` with the same filters and sort as today.
2. Row click → `handleSelect(entry, index)` in the workspace hook sets `focusedIndex` and calls the lazy query to fetch full ledger lines.
3. `focusedIndex` flows down through the page → `JournalEntriesTable` → `EntityTable` for keyboard-nav highlight styling.
4. Source navigation in the context header calls `navigateToSource` — same routing map as today, moved from the table into the header.

No new API calls. No new state beyond `focusedIndex`.

## Error Handling

No new error paths. Existing list query and lazy single-entry fetch error handling is unchanged.

## Acceptance Criteria

- Journal Entries list page uses `EntityTable` with no checkboxes or action buttons.
- No "New Journal Entry" button on the list page.
- Context header is read-only: shows reference, date, description, debits, credits, status, source link. No action buttons.
- `JournalEntryFormPage` is deleted and its routes are removed.
- Visual consistency with COA, Sales Orders, and Purchase Orders pages.
- All existing tests pass or are updated to reflect the new read-only behavior.
