# semantic-release v25 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `semantic-release`, `@semantic-release/github`, and `@semantic-release/npm` to their latest major versions and add the required GitHub token permissions.

**Architecture:** Three mechanical changes — bump version ranges in `package.json`, add two permission entries in `release.yml`, regenerate the root `package-lock.json`. No logic changes anywhere.

**Tech Stack:** npm, semantic-release v25, @semantic-release/github v12, @semantic-release/npm v13, GitHub Actions

---

## Chunk 1: Version bumps + permissions + lockfile

**Files:**
- Modify: `package.json` (root)
- Modify: `.github/workflows/release.yml`
- Modify: `package-lock.json` (root, regenerated by npm)

### Task 1: Bump version ranges in `package.json`

**Files:**
- Modify: `package.json`

- [ ] **Step 1: Update the three version ranges**

Open `package.json` at the repo root. Make these three changes:

| Package | From | To |
|---|---|---|
| `semantic-release` | `"^24.0.0"` | `"^25.0.0"` |
| `@semantic-release/github` | `"^10.0.0"` | `"^12.0.0"` |
| `@semantic-release/npm` | `"^12.0.0"` | `"^13.0.0"` |

The full file after the change should look like:

```json

    "@semantic-release/commit-analyzer": "^13.0.0",

```

- [ ] **Step 2: Verify the edit**

Run: `cat package.json`

Expected: the three updated ranges appear, all other entries unchanged.

### Task 2: Add permissions to `release.yml`

**Files:**
- Modify: `.github/workflows/release.yml`

- [ ] **Step 1: Add `issues: write` and `pull-requests: write` to the `release` job**

The `release` job currently has:

```yaml
    permissions:
      contents: write
```

Change it to:

```yaml
    permissions:
      contents: write
      issues: write
      pull-requests: write
```

Do NOT touch the top-level `permissions: contents: read` block (lines 11-12) — that is a workflow-level default and is intentionally left as-is. Only the job-level block under `jobs.release` needs updating.

- [ ] **Step 2: Verify the edit**

Run: `cat .github/workflows/release.yml`

Expected: the `release` job permissions block shows all three entries. The `build-and-push` job is unchanged.
