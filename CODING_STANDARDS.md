# Coding standards

These rules require judgment across files. Put mechanically enforceable rules in lint, hooks or checks.

- **Steering docs and linked topic docs have one source of truth.** Keep each fact in one authoritative place. Other mentions are pointers naming the subject and when to follow it. When relocating guidance, preserve prerequisites, explicit obligations and meaningful references (including “above/below” targets), and consolidate against existing destination content. A finding that asks to replace a restatement with a pointer names the surviving location; the fix confirms that location holds the full meaning. Incidents: #1697, #1698, PR #1708; #1707, PR #1730 (a pointer dropped the owner-confirmed merge rule because its target never held all of it).
- **Frontend API tests exercise the backend response shape.** Check the controller, DTO and any response wrapper; return that shape from mocks and type the API call against it instead of `any`. Keep shared response types in the owning domain under `frontend/src/types`. A type used by one component may stay local; move it to the shared location when another consumer needs it. Both must match the backend response shape. Incident: #1703, fixed in PR #1716.
- **Agent docs hold durable rules.** Put one-off plans, issue-specific actions and closure steps in the issue. Incident: PR #1720, which removed an issue-specific follow-up plan from the development reference.
- **Removing a mechanism includes updating its reasons.** Search comments and docs for explanations that depend on the removed plugin, step or behavior, then update them to explain the current design. Incident: PR #1720: release auto-commit explanations and the development reference’s release-retrigger justification for `--ff-only` survived removal of the version commit.
- **One pinned version has one source.** Declare a dependency used by tests and runtime once, and install both from that declaration. Incident: PR #1720: the changelog preset version appeared in both the root manifest and release workflow.
- **Checker documentation matches its code.** Verify claims about accepted, skipped and rejected inputs against the implementation, including exceptions and resolution order. Incident: #1705, PR #1723: pointer-check documentation omitted accepted and skipped cases.
- **Script tests use a CI-discovered layout.** Keeping both existing shell-test layouts is deliberate: backend Bats covers backend scripts, while the root git-hook integration suite retains its existing responsibility. Backend shell tests use Bats in `backend/scripts/__tests__`, run by the backend CI job via `npm run test:scripts`. New root script tests go in `scripts/__tests__`, using Node’s default recursive test discovery (including `*.test.js`, `*.test.mjs`, `*.test.cjs`, and JavaScript files inside nested `test/` directories); they may invoke shell scripts. Keep helpers outside discovered paths. For the root test command and CI step, follow the change-scoped verification table in [AGENTS.md](AGENTS.md#change-scoped-verification-required-before-merge). Extend `scripts/tests/git-hooks.sh` for the existing git-hook integration suite’s responsibility. Each layout needs a CI step that runs it with its dependencies. Incidents: #1704, PR #1718.
- **Committed app versions remain baselines.** Reject PRs that “fix” the committed versions in [backend/package.json](backend/package.json) or [frontend/package.json](frontend/package.json). For how releases stamp versions, read [release versions and verification](docs/agents/development-reference.md#release-versions-and-verification). Incident: #1704, PRs #1720 and #1721.
- **Commit and PR bodies state traceable evidence.** Each claim about a decision, review or test run names its source (issue comment, command, reviewed SHA) and the commit it ran on. Write "not yet verified" for anything else. For review citations, follow the [review citation convention](docs/agents/code-review.md#citations). Incidents: #1706, PR #1727 (an "owner conventions" commit preceded the owner's decision, and an amended body misattributed it to review messages); #1724, PR #1756 (a review-pass claim had no ledger).
  - Test counts and pass claims quote the runner's own summary from saved output; for TAP, quote the plan line and the ok/not-ok counts. Never count from partial output. Incident: PR #1730 reported 37, then 77 script tests; the suite had 82.
  - In `docs/verification/` records, copy every count from the output of the command shown beside it, keep embedded scripts byte-identical to the scripts that ran, and cite the check showing any claimed revert or restore. Incident: PR #1733 (mismatched counts and embedded script, and an unsupported revert claim).
  - Save output quoted as evidence in the key's [evidence directory](docs/agents/code-review.md#state-and-reports). Incident: #1717, PR #1749 (a test-count claim cited ephemeral `/tmp` output).
