# Coding standards

These rules require judgment across files. Put mechanically enforceable rules in lint, hooks or checks.

- **Steering docs and linked topic docs have one source of truth.** Keep each fact in one authoritative place. Other mentions are pointers naming the subject and when to follow it. When relocating guidance, preserve prerequisites, explicit obligations and meaningful references (including “above/below” targets), and consolidate against existing destination content. Incidents: [#1697](https://github.com/blur88/erp2/issues/1697), [#1698](https://github.com/blur88/erp2/issues/1698), [PR #1708](https://github.com/blur88/erp2/pull/1708).
- **Frontend API tests exercise the backend response shape.** Check the controller, DTO and any response wrapper; return that shape from mocks and type the API call against it instead of `any`. Put response types shared across consumers in the owning domain under `frontend/src/types`; a response type used by one component may stay local. Incident: [#1703](https://github.com/blur88/erp2/issues/1703), fixed in [PR #1716](https://github.com/blur88/erp2/pull/1716).
- **Agent docs hold durable rules.** Put one-off plans, issue-specific actions and closure steps in the issue. Incident: [PR #1720](https://github.com/blur88/erp2/pull/1720), which removed an issue-specific follow-up plan from the development reference.
- **Removing a mechanism includes updating its reasons.** Search comments and docs for explanations that depend on the removed plugin, step or behavior, then update them to explain the current design. Incident: [PR #1720](https://github.com/blur88/erp2/pull/1720): release auto-commit explanations survived removal of the version commit.
- **One pinned version has one source.** Declare a dependency used by tests and runtime once, and install both from that declaration. Incident: [PR #1720](https://github.com/blur88/erp2/pull/1720): the changelog preset version appeared in both the root manifest and release workflow.
- **Script tests follow the owning runner.** Add backend shell tests to `backend/scripts/__tests__` using Bats; add root Node tests to `scripts/__tests__`. Extend an existing shell integration suite in its established location. Ensure CI runs each chosen layout with its required dependencies. Incidents: [#1704](https://github.com/blur88/erp2/issues/1704), [PR #1718](https://github.com/blur88/erp2/pull/1718).
- **Checker documentation matches its code.** Verify claims about accepted, skipped and rejected inputs against the implementation, including exceptions and resolution order. Incident: [#1705](https://github.com/blur88/erp2/issues/1705), [PR #1723](https://github.com/blur88/erp2/pull/1723): pointer-check documentation omitted accepted and skipped cases.
